## Summary

Execute a comprehensive architectural hardening and refactoring based on 3 Core Architectural Laws: (1) API key ≠ Quota bucket (`QuotaGroup` authority without false capacity summing), (2) Model syntax-valid ≠ Model verified (Singleflight Promise-lock & non-blocking hot path), and (3) Provider attempt ≠ Logical user request (Telemetry & metrics disambiguation). Hardens AES-256-GCM server encryption, scoped idempotency, scoped circuit breaker, and Redis graceful degradation.

## High-Level Implementation Strategy

1. **Phase 1 (Security & Idempotency Hardening - P0)**:
   - Implement AES-256-GCM encryption/decryption in `server/services/sessionStore.ts`.
   - Ensure payload conflict 409 detection in `server/middleware/idempotencyMiddleware.ts`.
   - Verify telemetry redaction in `server/utils/text.ts` and loggers.
2. **Phase 2 (Quota Group & Key Health Decoupling - P0/P1)**:
   - Verify `QuotaGroup` authority in `server/services/quotaService.ts` to prevent false capacity summing.
   - Verify `AUTH_FAILED` key isolation in `quotaService.ts` and `geminiService.ts`.
3. **Phase 3 (Model Verification & Singleflight - P1)**:
   - Confirm 5-state lifecycle and singleflight deduplication in `modelInfoService.ts`.
4. **Phase 4 (Error Taxonomy, Circuit Breaker & Concurrency Gate - P1)**:
   - Confirm scoped circuit breaker `[QuotaGroupId + ModelId]` in `quotaService.ts`/`geminiService.ts`.
   - Confirm `MAX_CONCURRENT_REQUESTS = 50` in `geminiService.ts`/`rateLimiter.ts`.
5. **Phase 5 (Redis Degradation & Metrics - P1/P2)**:
   - Verify fallback in `redisService.ts` and health probes.
   - Enhance `metricsService.ts` with explicit `logicalRequests` vs `providerAttempts` counters.
6. **Phase 6 (Frontend & Quality Gates - P2)**:
   - Validate `QuotaPanel.tsx` and `ApiSettings.tsx`.
   - Run `npm run lint`, `npm test`, `npm run build`.

# Implementation Plan: Strict Glossary Runtime Validation and End-to-End Typing Hardening

**Branch**: `159-glossary-strict-validation` | **Date**: 2026-09-23 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/159-glossary-strict-validation/spec.md`

## Summary

This feature resolves the 3 remaining technical debt and validation gaps identified during the audit of commit `c1b8b2b`:
1. **Item-Level Glossary Runtime Validation (P1)**: Implement `isGlossarySuggestionItem` in `src/lib/text.ts` and wire it into `directGlossaryEngine.ts` to drop malformed or empty items (`{}`, `chinese: 123`, `vietnamese: null`, `chinese: ""`) rather than coercing them into blank/phantom cards.
2. **Prevent Empty Chinese Strings in Snap-Back Normalization (P1)**: Add empty/whitespace check in `validateAndSnapBackEntities` (`src/lib/sinoNormalize.ts`) to prevent `rawText.includes("")` from matching and creating phantom entries.
3. **End-to-End `any[]` Elimination (P2)**: Replace `as any[]` in `directGlossaryEngine.ts` with `unknown[]` filtered with `isGlossarySuggestionItem`. Replace `let detectedQaIssues: any[] = []` in `chapterTranslationService.ts` with `DirectQaCritiqueIssue[]`. Replace `glossary?: any[]` in `DirectQaCritiqueParams` (`src/services/translation/types.ts`) with `GlossaryItem[]`.
4. **Documentation & Specification Synchronization (P3)**: Ensure all design artifacts (`data-model.md`, `spec.md`, `contracts/internal-contracts.md`) accurately describe `GlossarySuggestion extends Omit<GlossaryItem, 'id'>`.

## Planned Implementation Phases

### Phase 1: Item-Level Glossary Guard & Snap-Back Defense
1. In `src/lib/text.ts`:
   - Implement `isGlossarySuggestionItem(item: unknown): item is GlossarySuggestion`.
   - Strictly validate `chinese` (or `term`) as non-empty string, `vietnamese` as string, `type` as valid `GlossaryType`, `pinyin`/`note` as string if present.
2. In `src/lib/sinoNormalize.ts`:
   - Guard `validateAndSnapBackEntities` to filter out any entity where `!item || typeof item.chinese !== 'string' || !item.chinese.trim()`.
3. Add unit tests in `src/lib/__tests__/text.test.ts` and `src/lib/__tests__/sinoNormalize.test.ts`.

### Phase 2: Pipeline Wiring & Internal `any[]` Elimination in Glossary Engine
1. In `src/services/directGlossaryEngine.ts`:
   - In `callGlossaryAnalysisDirect`: parse as `unknown[]`, filter via `isGlossarySuggestionItem`, map conforming items.
   - In `extractGlossaryDirect`: parse as `unknown[]`, filter via `isGlossarySuggestionItem`, map conforming items.
   - Remove all occurrences of `as any[]`.
2. Add unit tests in `src/services/__tests__/directGlossaryEngine.test.ts` asserting that corrupt items (`{}`, `chinese: 123`, `vietnamese: null`) are discarded.

### Phase 3: Translation Service Type Hardening
1. In `src/services/chapterTranslationService.ts`:
   - Import `DirectQaCritiqueIssue` and type `detectedQaIssues: DirectQaCritiqueIssue[] = []`.
2. In `src/services/translation/types.ts`:
   - Update `DirectQaCritiqueParams.glossary?: GlossaryItem[]`.

### Phase 4: Full Quality Gate Verification
1. Run `npm run lint` (`tsc --noEmit`) to verify 0 type errors.
2. Run `npm test` (`vitest run`) to verify 100% test pass rate.
3. Run `npm run build` (`tsc && vite build`) to verify clean production build.

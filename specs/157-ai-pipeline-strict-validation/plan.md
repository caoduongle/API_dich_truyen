# Implementation Plan: AI Pipeline Strict Validation and Structural Integrity

**Branch**: `157-ai-pipeline-strict-validation` | **Date**: 2026-09-22 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/157-ai-pipeline-strict-validation/spec.md`

## Summary

Following the hardening pass in commit `601a9a58`, audit identified remaining structural validation gaps:
1. **QA Validator Loose Schema (P1)**: `isQaCritiqueResponse({})` evaluates to `true`, causing malformed or empty AI responses to be silently accepted as "no errors found" (`isValid: true, issues: []`).
2. **QA Issue Coercion (P2)**: Non-conforming issue items (e.g. primitives, empty objects) are coerced into empty warning objects rather than filtered out, creating phantom warnings in the review UI.
3. **Discovered Entity Normalization vs Validation (P1/P2)**: `validateDiscoveredEntity` converted non-string types to empty strings rather than rejecting malformed entity payloads. As agreed (Option A), non-string types must be strictly rejected while omitted fields default to empty strings.
4. **Cumulative Deadline Trailing Overshoot (P2)**: An attempt floor of 1000ms (`Math.max(1000, ...)`) allows stalled attempts to exceed the cumulative deadline by up to 1s.
5. **Secondary Structured AI Output Boundaries (P2 Tech Debt)**: Secondary services (`directGlossaryEngine.ts`, `directGeminiClient.ts` Quick Term, `hakoQualityEngine.ts`) use unvalidated JSON casting. As agreed (Option A), all secondary structured outputs must adopt runtime schema guards.

## Planned Implementation Phases

### Phase 1: Core QA Critique & Entity Validation Hardening
1. Update `QaCritiqueResponse` and `isQaCritiqueResponse` in `src/lib/text.ts` to require `isValid: boolean` and `issues: unknown[]`.
2. Add `isQaCritiqueIssue` helper in `src/lib/text.ts` or `qaCritique.ts` to strictly validate issue items.
3. Update `qaCritiqueDirect` in `src/services/translation/qaCritique.ts` to filter out invalid issues via `.filter(isQaCritiqueIssue)`.
4. Update `validateDiscoveredEntity` in `src/lib/text.ts` to strictly reject non-string types for present entity attributes (Option A).
5. Update `src/lib/__tests__/text.test.ts` to assert that `{}` is rejected by `isQaCritiqueResponse`, and add tests for strict entity rejection.

### Phase 2: Cumulative Deadline Hard Cap
1. Update `src/services/gemini/geminiClient.ts` to remove `Math.max(1000, ...)`.
2. Implement pre-dispatch deadline check (`remainingMs <= 50` throws `TimeoutError`).
3. Add/update tests in `src/services/gemini/__tests__/geminiClient.test.ts` verifying sub-second remaining time handling.

### Phase 3: Secondary Structured AI Output Boundary Unification
1. Define runtime schema validators in `src/lib/text.ts` or respective service files:
   - `isQuickTermResponse`
   - `isGlossarySuggestionsResponse`
   - `isGuidelinesAnalysisResponse`
   - `isAlignChapterResponse`
   - `isHakoQualityScanResponse`
2. Integrate validators into `directGeminiClient.ts`, `directGlossaryEngine.ts`, and `hakoQualityEngine.ts`.
3. Add unit tests for secondary service parsing error recovery.

### Phase 4: Full Quality Gate Verification
1. Run `npm run lint` (`tsc --noEmit`).
2. Run `npm test` (`vitest run`).
3. Run `npm run build` (`tsc && vite build`).

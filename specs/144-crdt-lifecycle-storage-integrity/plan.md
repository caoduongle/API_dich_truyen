# Implementation Plan: CRDT Lifecycle, Storage Integrity, and Lock Isolation Hardening

**Branch**: `144-crdt-lifecycle-storage-integrity` | **Date**: 2026-09-17 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/144-crdt-lifecycle-storage-integrity/spec.md`

## Summary

Resolve critical storage integrity and CRDT lifecycle issues across client-side IndexedDB and Web Locks:
1. Ensure `deleteProjectCrdtDatabases` resolves strictly on `onsuccess`, handles `onblocked` with bounded timeout/rejection, and avoids false positives on `onerror`.
2. Cleanly unmount and destroy active in-memory `IndexeddbPersistence` connections prior to database deletion.
3. Eliminate naive prefix matching (`startsWith("crdt_" + projectId + "_")`) to prevent accidental deletion of sibling projects sharing prefix IDs (e.g. `proj_123` vs `proj_123_456`), deriving exact database names `crdt_${projectId}_${chapterId}` from known project chapters.
4. Enhance `deleteChapterFromDB` to atomically remove records from `CHAPTERS_STORE` and `CRDT_STATES_STORE`, resolve on `transaction.oncomplete`, and purge the dedicated `crdt_${projectId}_${chapterId}` database.
5. Apply fail-closed validation for CRDT states in `saveCrdtState` and `saveCrdtStates` (reject/omit records without `projectId`), and validate project ID matching in `atomicSaveProjectBundle` (reject mismatch).
6. Isolate Web Lock retry mechanics in `withProjectLock` so that application errors thrown inside user callbacks are never retried.
7. Support full CRDT restoration on project deletion Undo (`getCrdtStatesByProject`).

## Proposed Changes

### Component 1: In-Memory CRDT Persistence Registry (`src/services/crdtPersistenceRegistry.ts`)
- Maintain a singleton `Map<string, IndexeddbPersistence>` tracking active `y-indexeddb` instances in the current window.
- Provide `registerCrdtPersistence(dbName, provider)`.
- Provide `unregisterCrdtPersistence(dbName, provider)`.
- Provide `destroyCrdtPersistence(dbName)`.
- Provide `destroyAllCrdtPersistencesForProject(projectId, knownChapterIds)`.
- Integrate into `useChapterCRDT.ts` during initialization and cleanup.

### Component 2: Storage Integrity & Safe Deletion (`src/services/db.ts`)
- **`deleteProjectCrdtDatabases`**:
  - Close active persistences first via `destroyAllCrdtPersistencesForProject`.
  - Disallow naive `startsWith("crdt_" + projectId + "_")`.
  - Target exact derived database names `crdt_${projectId}_${chapterId}` from known chapter IDs.
  - Wrap `indexedDB.deleteDatabase`: resolve strictly on `onsuccess`; on `onblocked`, log warning and wait for `onsuccess` with bounded 5000ms timeout; on `onerror`, reject.
- **`deleteChapterFromDB`**:
  - Discover `projectId` if not supplied.
  - Enqueue write via `enqueueProjectWrite(projectId)`.
  - Delete record from `CHAPTERS_STORE` and `CRDT_STATES_STORE` in a single transaction.
  - Resolve strictly on `transaction.oncomplete`.
  - Call `destroyCrdtPersistence` and delete `crdt_${projectId}_${chapterId}`.
- **`deleteChaptersByProjectFromDB`**:
  - Change cursor iteration to resolve strictly on `transaction.oncomplete`.
- **`saveCrdtState` & `saveCrdtStates`**:
  - Fail-closed: omit/warn on records missing `projectId`.
- **`atomicSaveProjectBundle`**:
  - Validate that every CRDT item with `projectId` matches `project.id`. Throw immediate `Error` on mismatch.
- **`getCrdtStatesByProject(projectId)`**:
  - Query all CRDT states belonging to a project for backup/undo.
- **`withProjectLock`**:
  - Use `LockOutcome<T>` so `fn()` is wrapped in `try...catch`. Application errors resolve the lock callback without triggering `withRetry` re-acquisition.

### Component 3: Project & Chapter Hook Undo Hardening (`src/hooks/useProjects.ts`)
- In `handleDeleteProject`:
  - Back up `backedUpCrdtStates = await getCrdtStatesByProject(id)`.
  - On Undo: restore `saveProjectToDB`, `saveChaptersToDB`, and `saveCrdtStates(backedUpCrdtStates)`.
- In `handleDeleteChapter`:
  - Back up `backedUpCrdt = await getCrdtState(chapId)`.
  - On Undo: restore `saveChapterToDB` and `saveCrdtState(backedUpCrdt)`.

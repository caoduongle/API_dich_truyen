# Implementation Plan: Strict QA Issue Validation and Secondary Pipeline Hardening

**Branch**: `158-qa-issue-strict-hardening` | **Date**: 2026-09-22 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/158-qa-issue-strict-hardening/spec.md`

## Summary

This feature resolves the final P1 issue and remaining P2 technical debt identified in the audit of commit `2f234ef`:
1. **Strict QA Issue Validation (P1)**: Enforce mandatory presence and valid types for all 4 primary issue fields in `isQaCritiqueIssue` (`type`, `severity`, `targetText`, `description`/`message`), dropping incomplete issue items at runtime rather than coercing them into default warning cards.
2. **Item-Level Hako Scan Issue Validation (P2)**: Implement `isHakoQualityScanIssue` to validate individual entries in `HakoQualityScanResponse.issues`, eliminating unchecked type casts (`as any`).
3. **Strongly-Typed Glossary Pipeline (P2)**: Replace `any[]` throughout `src/services/directGlossaryEngine.ts` with a concrete `GlossarySuggestion` interface.
4. **Comprehensive Prompt Sanitization (P2)**: Sanitize `options.genre` in `quickTranslateTermDirect` and `projectTitle` / `chapter.title` in Hako quality scan using `sanitizePromptInput`.

## Planned Implementation Phases

### Phase 1: Strict QA Critique Issue Validation (Priority: P1)
1. Update `isQaCritiqueIssue` in `src/lib/text.ts` to require all 4 primary fields:
   - `type` required in `['omission', 'addition', 'repetition', 'terminology', 'other']`.
   - `severity` required in `['critical', 'warning', 'info']`.
   - `targetText` required string.
   - `description` or `message` required non-empty string.
2. In `src/services/translation/qaCritique.ts`, rely directly on validated issue fields from `isQaCritiqueIssue`.
3. Update tests in `src/lib/__tests__/text.test.ts` and `src/services/translation/__tests__/qaCritique.test.ts`.

### Phase 2: Hako AI Scan Item-Level Validation (Priority: P2)
1. Implement `isHakoQualityScanIssue` in `src/lib/text.ts`.
2. In `src/services/hakoQualityEngine.ts`, filter raw AI response issues using `isHakoQualityScanIssue`.
3. Add unit tests for item-level rejection in `src/lib/__tests__/text.test.ts` and `src/services/__tests__/hakoQualityEngine.test.ts`.

### Phase 3: Strongly-Typed Glossary Pipeline (Priority: P2)
1. Define `GlossarySuggestion` interface in `src/lib/text.ts`.
2. Replace `any[]` in `src/services/directGlossaryEngine.ts` with `GlossarySuggestion[]`.
3. Verify type correctness across downstream consumers via `npm run lint`.

### Phase 4: AI Prompt Metadata Sanitization (Priority: P2)
1. In `src/services/directGeminiClient.ts`, pass `options.genre` through `sanitizePromptInput`.
2. In `src/services/hakoQualityEngine.ts`, pass `projectTitle` and `chapter.title` through `sanitizePromptInput`.
3. Add unit tests in `src/services/__tests__/directTranslationEngine.test.ts` and `src/services/__tests__/hakoQualityEngine.test.ts`.

### Phase 5: Full Quality Gate Verification
1. Run `npm run lint` (`tsc --noEmit`) to verify 0 type errors.
2. Run `npm test` (`vitest run`) to verify 100% test pass rate.
3. Run `npm run build` (`tsc && vite build`) to verify clean production build.
